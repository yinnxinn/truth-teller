# 微信公众号自动化仓库整合设计

## 文档定位

本文记录当前仓库由早期单机工作区演进为公开项目后的目录边界。历史迁移已经完成；旧机器目录和回滚副本不再作为安装、测试或验收前提。

## 目标

在同一仓库中维护可独立安装的 Codex Skill 与公众号内容实验工作区，同时让新用户只靠仓库内相对路径就能理解、安装和验证稳定核心。

## 边界

- `skill/` 是可移植、可测试、可独立安装的稳定核心。
- `app/` 保存依赖本机浏览器、历史素材或公众号登录态的实验脚本，不承诺跨环境直接运行。
- `content/`、`assets/`、`runs/` 与 `logs/` 只保存允许公开且可复现的材料；私密草稿和运行产物默认不入库。
- 自动化只允许在用户明确授权后保存草稿，不自动发表文章。

## 结构

`skill/SKILL.md` 定义产品行为；`skill/scripts/` 提供 HTML 生成与注入辅助脚本；`app/` 保留完整工作区的实验入口；根目录 README、贡献指南和 CI 负责公开项目的安装与验证契约。

## 当前验收标准

1. `skill/` 可以复制到 Codex Skills 目录并通过官方校验。
2. `python -m pytest skill/tests tests -v` 在干净克隆中通过。
3. README 明确区分稳定内容生成与实验后台自动化。
4. 仓库不跟踪密钥、Cookie、浏览器会话、账号截图或用户私人草稿。
5. 现有 `app/`、`content/` 和 Git 历史在整合中得到保留。
