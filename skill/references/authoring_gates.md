# 成稿门禁 SOP（复杂/长篇文章的写稿与放行流程）

> 适用：对"解构 + 评论"的**复杂或较长**文章（涉公司/财报/综合/健康等素材时尤其需要），把它当一稿正式产物来走，而不是一条流水线一次写完就交。
> 写法：**给读者看的话全用白话**；文末附"朝廷称呼对照表"只作内部术语，供开发/产物字段复用。
> 断点原则：**写与批分离、每个环节都有权说"不"、涉高风险未出《来源清单》不放行到交付。**

---

## 从素材到可发表，共 6 道门（每道门产出"该环节的件"并留痕）

### ① 选题门 — 这件事值不值得做？现在做还是存着？

输入：原始素材 / 链接 / 用户一句话。
该环节做的事：
- 辨"主体"：谁在说话（公司/个人/自媒体），想让人信什么，读者是谁。
- 辨"为什么是现在"：是时效新闻还是常青话题；我们聊过同类没有（避免自我重复）。
- 辨"够不够硬"：有没有可核实的原文/数字可抓，还是只能空谈。

**通过才放行**：主题有明确争议/价值点，且至少有 1 处"可落地的核"(原文或数字或公认背景)。
**不过**：把这件事落到"待写池"，不急。

产出（如有风险或拿不准，落成一小段）：`《选题卡》：主张一句话 + 读者 + 核点来源`。

### ② 骨架门 — 这篇用哪种架子？

按素材形态选（白话讲，就是："这篇要怎么组织"）：

| 素材更像 | 建议骨架 |
|---|---|
| 公司信/财报/话术 | 解构式：先给"一句话戳穿" → 逐条拆 → 判词 |
| 被误读的客观利好/被当坏的改进 | 翻案式：给"说得通的另一种读法" → 摆依据 → 收 |
| 教读者动作(工具/方法) | 教程式：钩子 → 第1/2/3步 → 注意与坑 |
| 普遍痛点但无新闻味 | 观点式：抛出反直觉主张 → 立论几段 → 收束 |
| 轻量吐槽 | 清单式 / 杂志式 |

**通过才放行**：选定架子，且知道开头("钩子")和结尾("不烂尾")想干什么。
产出：`《骨架卡》：体裁 + 开头钩子用意 + 每段一句话目标`。

### ③ 成稿门 — 主笔把初稿写出来

按骨架写全文。要求同时满足：
- 原文引用**只来自已给/已核实的材料**，不凭印象补写"他说"。
- 推断写成评论/问题，不写成事实；黑话尽量还原成具体责任与成本。
- 落点是"组织/权力结构"，不是攻击某个人的长相、地域、隐私。
- 一稿里有"真相翻译官 / 毒舌拆解 / 判词"这种熟悉的骨头也OK，但不再被默认捆绑成唯一模板——看②选的架子。

产出：`初稿.md`。若涉及高风险可先顺手给 《待核来源清单》。

### ④ 定稿门（批红）— 这版"像不像我们该发的"

只审"腔调与定夺"，不改内容细节：
- 戳不戳得住？有没有只是刻薄、没有落到结构问题。
- 有没有为效果过度牺牲了边界(把观点说成事实 / 蹭了个不该蹭的名号)。
- 开头抓人、结尾不烂尾吗。

通过 → 交下一道；不过 → 明确"改哪一句/哪一段"退回③。
产出：`定稿批语`(可空，但**有必要就必须在此说清)**。

### ⑤ 质检门（语言/结构） — 逐字看会不会砸招牌

- 错字 / 长句绕 / 读不顺。
- 逻辑跳变(明明前面 A 结尾变 B)。
- 有"我编的数字 / 我猜的一定会爆"这类没出处断言。
- 有没有攻击具体个人的红线越界。

不过 → 直接退回③，并写明毛病；绝不因"写手觉得没毛病"而放行。
产出：`质检意见`(命中即录)。

### ⑥ 签发门（来源复核 + 红线再确认） — 到交付前的最后一道

- 有原文/数字处：确认有出处且说人话可回溯；没有就删或改"未证实"措辞。
- 涉新闻/财报/健康/法律/金融：**必须**产出一份 `《来源 & 认真脸》`（列出用到的来源；加"本评论不替代专业建议，请核权威来源"）。
- 终检是否有"对外不能露的批注/占位/调试"。

通过 → 进入交付(微信版 HTML 由对应安全生成脚本产，人在本地审，再人工粘贴/填草稿)。
